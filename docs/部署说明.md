# 公司官网部署

以下为通用 Linux 部署示例，域名 `www.example.com`、目录和资源参数均需按公司环境调整，不对应任何个人测试服务器。

## 构建与数据库

使用 Java 17+、Node.js 20.19+ / 22.12+、Maven 3.9+、MySQL 8.0+。在仓库根目录构建：

```sh
cd frontend
npm ci
npm run build
cd ..
mvn -f website/pom.xml package
```

将 `website/target/xgsz-website-1.0.0.jar` 复制为部署目录中的 `app.jar`。JAR 包含官网和后台网页，无需另开前端开发服务。

按 [数据库说明](../database/README.md) 创建 MySQL 库并导入 `init.sql`。数据库可以独立部署；创建只用于该项目的应用账号，配置公司自己的数据库地址、账号和密码。已导入 SQL 的部署无需在应用启动时自动建表。

## 服务配置

示例工作目录为 `/opt/xgsz-website`，Linux 服务账号为 `xgsz`。创建该账号和目录，将 JAR 放入目录，并把 `scripts/deploy/app.env.example` 复制为目录下的 `app.env`：

```sh
sudo useradd --system --home /opt/xgsz-website --shell /usr/sbin/nologin xgsz
sudo install -d -o xgsz -g xgsz /opt/xgsz-website
sudo install -m 644 website/target/xgsz-website-1.0.0.jar /opt/xgsz-website/app.jar
sudo install -m 600 scripts/deploy/app.env.example /opt/xgsz-website/app.env
sudo chown xgsz:xgsz /opt/xgsz-website/app.jar /opt/xgsz-website/app.env
```

编辑 `app.env`，填入实际数据库密码。模板不包含可用密码。`XGSZ_PORT=8080`，Java 默认仅绑定 `127.0.0.1`。通过环境变量配置端口时，同时调整 Nginx 的 `proxy_pass`。

将 `scripts/deploy/xgsz-website.service` 复制到 `/etc/systemd/system/`；目录、Java 路径、服务账号和内存限制按实际环境修改：

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now xgsz-website
curl --fail http://127.0.0.1:8080/api/health
sudo journalctl -u xgsz-website -n 100
```

健康检查的 `data` 应包含 `status=ok`、`storage=database`、`database=MySQL`。若失败，检查 SQL 导入状态、连接参数、权限及日志。

## 域名与访问入口

`scripts/deploy/xgsz-website.nginx.conf` 提供 HTTP 反向代理模板，将 `www.example.com`、`example.com` 替换为公司的域名，并按系统发行版放入 Nginx 的站点配置目录。模板将官网、后台、API 和图片统一代理到本机 8080。

```sh
sudo nginx -t
sudo systemctl reload nginx
```

首次部署时限制管理入口访问，完成 `/admin.html` 的管理员初始化；正式开放前配置公司域名、HTTPS 和所需备案。模板未内置证书。MySQL 按公司的网络拓扑限制访问；本机部署时不应开放数据库端口到公网。`mysql-memory.cnf` 仅为可选的小内存样例，不应直接覆盖公司数据库配置。

## 内容、更新与备份

后台维护的产品、服务、业务方向、展示资料、联系方式、咨询和上传图片保存在 MySQL。页面标题、固定介绍和页脚等纯文案随源码交付，控制台不提供编辑入口。初始化 SQL 只包含公开默认内容；不会配送测试账号、运行数据或私人联系方式。

更新前备份数据库和当前 JAR，再替换 `app.jar` 并重启 `xgsz-website`。代码更新不需要重新导入初始化 SQL；涉及表结构变更时单独评估升级脚本。

```sh
mysqldump -u YOUR_BACKUP_USER -p --single-transaction --no-tablespaces xgsz_website > website-backup.sql
sudo systemctl restart xgsz-website
curl --fail http://127.0.0.1:8080/api/health
```

恢复或切换数据库前先停止应用，按公司备份流程执行。凭据、证书私钥、数据库备份和实际运行数据不得提交到仓库。
